# TBX Next版 STTR1

TBX Next版 STTR1 は、Mike Mayfield の 1972年版 `STAR TREK`（STTR1）を、TBX Next の現在の言語機能で再構成したサンプルゲームです。

原典とのソース互換や画面の逐語再現ではなく、銀河探索、戦闘、補給、装置損傷、勝敗までを通常のTBX Next実行環境で遊べることを目的としています。

## 実行方法

リポジトリのルートで次を実行します。

```sh
cargo run -p tbx-next -- docs/next/examples/sttr1/main.tbx
```

ゲーム開始時に、期限、撃破すべきクリンゴン数、スターベース数とコマンド一覧が表示されます。

## ゲームの目的

制限スターデート内に、銀河にいるすべてのクリンゴンを撃破すると勝利です。

主な敗北条件は次のとおりです。

- 期限を超える。
- シールドが攻撃によって0を下回り、エンタープライズが破壊される。
- 現在クアドラントにクリンゴンがおらず、エネルギーが0以下かつシールドが残っていない状態になる。

ゲームは勝利または敗北で終了し、結果と概要が表示されます。

## コマンド

入力するコマンド番号は 0 から 7 です。

| 番号 | 機能 | 用途 |
| ---: | --- | --- |
| 0 | ナビゲーション | コースとワープを指定して移動する |
| 1 | 短距離スキャン | 現在クアドラント内の8×8セクターと艦の状態を見る |
| 2 | 長距離スキャン | 現在クアドラントを中心とした3×3範囲を見る |
| 3 | フェイザー | エネルギーを投入して現在クアドラントのクリンゴンを攻撃する |
| 4 | 光子魚雷 | コースを指定して魚雷を発射する |
| 5 | シールド制御 | エネルギーとシールドの配分を変更する |
| 6 | 損傷レポート | 各装置の損傷状態を見る |
| 7 | ライブラリコンピューター | 銀河チャート、任務状態、クリンゴン情報を見る |

コマンド一覧はゲーム冒頭に表示されます。数値として解釈できない入力で `COMMAND INPUT ERROR` になった場合にも再表示されます。

## 座標

クアドラントとセクターはいずれも `X,Y` の順で表示します。

銀河は8×8クアドラントで、各クアドラントの内部も8×8セクターです。

## ナビゲーション

### コース

コースは原典の 1.0 から 8.x に相当する値を10倍した整数で入力します。

| 入力 | 方向 |
| ---: | --- |
| 10 | 東 |
| 20 | 北東 |
| 30 | 北 |
| 40 | 北西 |
| 50 | 西 |
| 60 | 南西 |
| 70 | 南 |
| 80 | 南東 |

11から19、21から29のような中間値も使えます。例えば15は東と北東の中間です。

入力範囲は `10..89` で、`0` はキャンセルです。

### ワープ

ワープも10倍した整数で入力します。

- `10` = ワープ1.0
- `80` = ワープ8.0
- 入力範囲は `0..80`

ワープ1.0はおおむね1クアドラント分の移動尺度です。

ワープエンジンが損傷している場合、最大入力は `2`（ワープ0.2）に制限されます。

## 短距離スキャン

短距離スキャンでは現在クアドラント内の8×8セクターを表示します。

| 記号 | 意味 |
| --- | --- |
| `P` | エンタープライズ |
| `K` | クリンゴン |
| `B` | スターベース |
| `*` | 星 |
| `.` | 空きセクター |

あわせて、次の状態がラベル付きで表示されます。

- スターデート
- コンディション
- 現在クアドラント
- 現在セクター
- エネルギー
- 光子魚雷数
- シールド

コンディションは `GREEN`、`YELLOW`、`RED`、`DOCKED` のいずれかです。

## 長距離スキャン

長距離スキャンは、現在クアドラントを中央にした3×3のクアドラント情報を表示します。

各クアドラントは3桁の `KBS` 形式です。

- 百の位: クリンゴン数
- 十の位: スターベース数
- 一の位: 星数

例えば `206` は「クリンゴン2、スターベース0、星6」です。1桁や2桁の値も `004`、`031` のように3桁で表示されます。

銀河の範囲外は `---` です。

正常なライブラリコンピューターがある場合、長距離スキャンで得た情報は銀河チャートにも記録されます。

## フェイザー

フェイザーでは、現在利用できるエネルギーを確認して投入量を入力します。

`0` 以下を入力するとキャンセルします。現在のエネルギーを超える値は受け付けません。

攻撃時には、各クリンゴンについてセクター座標、与えた損傷、残りエネルギーが表示されます。撃破した場合も対象座標が表示されます。

フェイザー射撃では、クリンゴン側の攻撃が先に解決されます。シールドが攻撃で破壊された場合、フェイザー攻撃は行われません。

## 光子魚雷

光子魚雷のコース入力はナビゲーションと同じ `10..89` の尺度を使い、`0` でキャンセルします。

発射すると残り魚雷数が表示されます。魚雷は現在クアドラント内を進み、最初に当たった対象またはクアドラント外への退出で終了します。

結果として次を区別して表示します。

- クリンゴン命中・撃破
- 星への命中
- スターベースへの命中・破壊
- ミス

発射後には、生存しているクリンゴンから反撃を受けます。

## シールド制御

シールド制御では、現在の `エネルギー + シールド` の合計から、新しいシールド量を指定します。

指定した量が新しいシールド値となり、残りがエネルギーになります。

`0` 以下を入力するとキャンセルします。利用可能な合計量を超える値は受け付けません。

## クリンゴンの攻撃

各クリンゴンの攻撃ごとに、攻撃元セクター、損傷量、攻撃後のシールド値が表示されます。

損傷量が0の場合も攻撃結果は表示されます。

ドッキング中はスターベースの防御を受けるため、クリンゴンの攻撃による損傷は発生しません。

## ドッキングと補給

エンタープライズの周囲8セクターのいずれかにスターベースがあるとドッキング状態になります。

ドッキングは短距離スキャン時に判定され、成立すると次の状態になります。

- エネルギーが最大値まで回復する。
- 光子魚雷が最大数まで補充される。
- シールドが0になる。
- コンディションが `DOCKED` になる。

短距離スキャンにも補給結果が表示されます。

## 装置損傷と修理

損傷レポートでは次の8装置を確認できます。

1. ワープエンジン
2. 短距離センサー
3. 長距離センサー
4. フェイザー制御
5. 光子魚雷発射管
6. 損傷制御
7. シールド制御
8. ライブラリコンピューター

損傷値が負の装置は使用不能または能力低下状態です。

有効なナビゲーションを行うと、損傷中の装置は1段階修理されます。また、移動時には一定確率でランダムな装置の状態が悪化または改善します。

損傷制御装置そのものが損傷している場合、損傷レポートは利用できません。

## ライブラリコンピューター

コマンド7では、続けて `0..2` の選択肢を入力します。

| 選択肢 | 機能 |
| ---: | --- |
| 0 | 銀河チャート |
| 1 | 任務状態 |
| 2 | 現在クアドラントのクリンゴン情報 |

### 銀河チャート

長距離スキャンで記録した8×8クアドラント情報を表示します。

現在クアドラントの座標、行・列の座標、`KBS` の意味も画面内に表示されます。未観測のクアドラントは `---` です。

### 任務状態

残りクリンゴン数、期限までの残りスターデート、残りスターベース数と損傷レポートを表示します。

### クリンゴン情報

現在クアドラント内の各クリンゴンについて、コースと距離を表示します。

コースはナビゲーションや光子魚雷と同じ10倍整数尺度です。距離はセクター距離の10倍整数で表示されます。

## 勝利と敗北

全クリンゴンを撃破すると勝利です。勝利時は経過スターデートと効率値が表示されます。

敗北時は、期限超過、エンタープライズ破壊、航行不能のいずれかの理由と、残りクリンゴン数が表示されます。

## 原典との主な違い

TBX Next版は原典のゲーム構造を保ちながら、現在のTBX Nextの整数中心の実装に合わせて再構成しています。

遊び方に関係する主な違いは次のとおりです。

- コースとワープは、原典の小数値を10倍した整数で入力する。
- 戦闘計算は整数化されているため、原典と同じ乱数系列や損傷値にはならない。
- 出力文面や画面配置は原典の逐語再現ではない。
- 勝敗後に原典のような自動再開始は行わず、1ゲームで終了する。

現在の挙動については、このREADMEよりも実装コードとテストを正本とします。
