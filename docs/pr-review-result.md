# PRレビュー結果の記録

この文書は、W01がPR全体のレビュー結果を機械的に判定するための正本文書である。PRの初回レビューと、修正後の再レビューまたは修正確認に適用する。

## 最終コメント

レビューまたは修正確認を終えるときは、対象head SHAと結果を含むmarkerを、最終PRコメントに1件含める。markerのv1形式は次のとおり。

```text
<!-- tbx-w01-review-result:v1 head=<40桁SHA> result=<changes_required|no_additional_changes> -->
```

- `head` は実際にレビューしたPR headの40桁commit SHAを指定する。コメントを投稿する時点でPR headを再取得するか確認し、その値を使う。
- `result` はレビュー回全体の結果を示す。`changes_required` はそのheadに追加修正が必要、`no_additional_changes` は追加修正が不要という意味である。
- markerは具体的な指摘の代わりにはならない。具体的な問題、影響する条件、修正方針、修正後に再確認した内容は、従来のPRレビュー運用に従って人間向けコメント本文に記録する。

例: `0123456789abcdef0123456789abcdef01234567` をレビューし、追加修正が不要だった場合、最終コメントに次の行を含める。

```text
<!-- tbx-w01-review-result:v1 head=0123456789abcdef0123456789abcdef01234567 result=no_additional_changes -->
```

## 有効性と失効

- marker付きコメントはレビュー結果記録であり、通常のレビュー指摘やフィードバックとして再処理しない。
- 現在headに対して有効な結果は、`head` が現在のPR head SHAと完全一致するものだけである。headが変化したら旧headの結果を新headへ引き継がない。
- 同一headに複数の結果がある場合、GitHub上で後に投稿されたmarkerを最新結果として扱う。
- `no_additional_changes` の記録後に通常の新しいレビュー指摘が追加された場合、または既存フィードバックに新しいrevisionが発生した場合、そのmarkerだけでレビュー完了とはみなさない。再レビューして新しい最終結果を記録する。
- markerがない既存PRでは、「merge ok」「LGTM」などの自由文から結果を機械的に推定しない。現在headのレビュー結果が記録されるまでレビュー待ちとして扱う。
- 自動化が結果を利用する場合も、対象PRの現在headとの完全一致を確認する。CI成功、未処理フィードバックがないこと、またはmessage単位の`no_change`だけからレビュー完了を推定しない。

## 形式の変更

この文書をmarker形式の唯一の正本とする。具体形式を変更するときはversionを更新し、旧versionとの互換性を明記する。別の運用文書や指示へmarker構文を複製せず、この文書への参照を置く。
